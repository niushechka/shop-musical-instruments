# Баг-репорты (PianoBar)

**Окружение:** Windows 11 (сборка 10.0.26200). Приложение PianoBar, WPF .NET 8.  
**Тестировщик:** Гуща Анна

### Баг 001: Товар добавляется в корзину без входа в карточке товара при нажатии «Добавить в корзину»

* **ID:** 001
* **Компонент:** Карточка товара (`ProductDetailsView`)
* **Серьезность (Severity):** Major
* **Приоритет (Priority):** High
* **Тестовые данные:** Любой товар с остатком на складе > 0

**Шаги для воспроизведения:**
1. Запустить PianoBar под гостем (в шапке каталога отображаются кнопки «Войти» и «Регистрация», активной сессии нет).
2. Открыть карточку любого товара.
3. Нажать кнопку «Добавить в корзину».

**Фактический результат:**  
Появляется сообщение «Товар добавлен в корзину». Товар сохраняется в корзине, хотя пользователь не авторизован в системе.

**Ожидаемый результат:**  
Как и в общем каталоге, должно появляться сообщение «Требуется авторизация», товар в корзину добавляться не должен.

**Примечания:**  
В общем каталоге по той же кнопке проверка сессии выполняется, а в отдельной карточке товара — проверка отсутствует.

### Баг 002: В корзине количество товара становится больше остатка на складе при нажатии «+»

* **ID:** 002
* **Компонент:** Корзина (`CartView`)
* **Серьезность (Severity):** Major
* **Приоритет (Priority):** High
* **Тестовые данные:** Пользователь в роли клиента; товар с известным остатком на складе (`Stock`)

**Шаги для воспроизведения:**
1. Войти в систему под учетной записью клиента.
2. Добавить товар в корзину (запомнить его остаток на складе).
3. Перейти в корзину.
4. Нажимать кнопку «+», увеличивая количество товара, пока оно не превысит остаток на складе.

**Фактический результат:**  
Количество товара в корзине увеличивается без ограничений. Сообщение «Недостаточно товара на складе» появляется только на последнем шаге при подтверждении заказа.

**Ожидаемый результат:**  
Кнопка «+» не должна увеличивать количество выше доступного остатка на складе. Пользователь должен сразу видеть ограничение.

**Примечания:**  
Проверка остатка товара выполняется только на этапе вызова `OrderService.CreateOrderAsync`, в логике корзины валидация отсутствует.

### Баг 003: Остаток товара не возвращается на склад при отмене заказа в профиле клиента

* **ID:** 003
* **Компонент:** Заказы (отмена в профиле клиента)
* **Серьезность (Severity):** Major
* **Приоритет (Priority):** High
* **Тестовые данные:** Клиент; товар в наличии; оформленный заказ в статусе «Ожидает подтверждения»

**Шаги для воспроизведения:**
1. Войти под клиентом.
2. Оформить заказ на товар в определенном количестве. Зафиксировать остаток товара на складе.
3. Открыть раздел «Мой профиль», найти оформленный заказ в статусе «Ожидает подтверждения».
4. Нажать «Отменить заказ» и подтвердить действие.
5. Открыть карточку товара в каталоге и проверить отображаемый остаток.

**Фактический результат:**  
Статус заказа меняется на «Отменен», но остаток товара на складе не увеличивается на количество отмененных единиц.

**Ожидаемый результат:**  
После отмены заказа, который еще не был отправлен или доставлен, списанное количество товара должно возвращаться на склад.

**Примечания:**  
Метод `CreateOrder` уменьшает `StockQuantity`, но метод `UpdateOrderStatusAsync` при установке статуса «Отменен» не возвращает остатки обратно.
